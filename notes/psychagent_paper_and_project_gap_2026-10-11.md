# PsychAgent 论文方法与 psych_sandbox 差距评估

核查日期：2026-10-11（Asia/Shanghai）。

这份笔记回答两个不同问题：论文到底实现了什么，以及当前仓库距离它还缺什么。论文事实来自 arXiv v3 和作者公开仓库；项目现状来自本仓库代码、测试和文档。论文分数不能直接证明临床疗效，项目中存在的模块也不能自动证明已经复现论文效果。

## 1. 先确认论文对象和“达到效果”的含义

这里的 PsychAgent 是 ECNU-ICALK 的 **PsychAgent: An Experience-Driven Lifelong Learning Agent for Self-Evolving Psychological Counselor**，arXiv:2604.00931v3，2026-04-28。它不是名称相近的 PsyAgent，也不只是一个“咨询师、来访者、督导师”组成的对话演示。

“达到 PsychAgent 效果”至少有三种含义：

1. **运行时相似**：能连续多次会谈，记住案例，按阶段规划，使用疗法技能，并从多个会谈候选中选出较好者。
2. **学习闭环相似**：能从高质量轨迹提炼新原子技能、合并技能，并把被选中的轨迹用于更新咨询师模型。
3. **论文结果相似**：在同一 PsychEval 切分、同一类模型规模、同一指标和独立评测协议下，达到论文报告的分数。

当前项目对第 1 项已经有较完整的工程实现，对第 2 项只具备数据结构和审核状态机的骨架，对第 3 项尚未有足够的训练、模型和人工实验。因此不能把“已经能运行多会谈”说成“已经达到 PsychAgent 的自演化效果”。

## 2. 论文的总体闭环

论文把咨询师建模成一个随经验更新的策略系统。每个会谈都有一个会前状态：

```text
上次的案例画像/摘要/目标
        ↓
记忆增强规划：预测治疗阶段和本场可执行目标
        ↓
按流派、阶段和目标选择技能
        ↓
咨询师与模拟来访者完成一整场会谈
        ↓
LLM 评审器给会谈打 reward
        ↓
保留最高 reward 的会谈，只有它推进后续记忆
        ↓
从高质量轨迹提炼/合并原子技能，并用拒绝微调内化经验
```

这里有两个容易混淆的层次：

- **推理时选优**：同一会谈起点生成多个完整候选，评分后只把赢家推进到下一场。
- **训练时内化**：把被拒绝的候选丢掉，把胜出轨迹作为监督信号更新模型参数。它不是 PPO/GRPO，也不是必须构造 chosen/rejected 成对损失的 DPO；论文给出的是 rejection fine-tuning 的胜出轨迹似然最大化。

## 3. Memory-Augmented Planning Engine（MAPE）

### 3.1 记忆保存什么

论文把长期状态拆成两类：

- **演化中的来访者画像**：随着新会谈证据更新。
- **会谈级情节摘要**：记录过去会谈发生了什么，供后续阶段和目标规划使用。

因此下一场不是把一长段逐字历史机械拼接到上下文，而是从结构化画像、摘要和当前会谈信息中恢复治疗连续性。规划器在会前预测治疗阶段，并生成本场可执行的 actionable objectives。

### 3.2 MAPE 的监督任务

论文将 MAPE 放进多任务监督微调（SFT）中。可确认的三个数据任务是：

- `D_mem`：从原始对话历史抽取结构化画像更新和会谈摘要；
- `D_plan`：从累计记忆预测治疗阶段和本场目标；
- `D_resp`：给定当前输入、记忆、计划和技能，生成咨询师的推理/回复。

论文式（2）把这些任务放在同一 SFT 目标中，形式可写为：

\[
\mathcal L_{SFT}=-\sum_{(x,y)\in D_{mem}\cup D_{plan}\cup D_{resp}}
\log P_\theta(y\mid x).
\]

这点很关键：论文的“记忆增强规划”不仅是提示词工程，还是让模型学会记忆抽取、规划和回复的训练目标。若只在运行时用 API 模型配上摘要提示词，可以实现相似控制流，但不能声称完成了论文中的 MAPE 参数学习。

## 4. Skill Evolution Engine（SEE）

### 4.1 技能树

技能是四层结构：

```text
therapeutic paradigm（治疗范式）
  → therapeutic stage（治疗阶段）
    → meta-skill（元技能）
      → atomic skill（原子技能）
```

范式和阶段先限制搜索空间；元技能是目标或策略类别；原子技能是能直接指导一次回复的具体做法。运行时选择到的原子技能会作为额外指令提供给咨询师生成。

### 4.2 从轨迹中长出技能

SEE 不是“每次把模型回复保存起来”这么简单。论文描述的流程是：

1. 在高 reward 会谈中找到与当前目标对齐的元技能分支；
2. 从该会谈提炼一个新的原子技能，要求它增加可复用的实践结构，而不是简单改写原句；
3. 在同一治疗范式、同一阶段内检索语义上最相近的现有原子技能；
4. 由技能管理策略决定是新增节点，还是把新经验合并进已有技能定义；
5. 对技能提取和管理也使用专门的 SFT 监督，并保留版本和树位置。

作者在附录中说明，最近邻比较用于判断新经验是否提供了额外实践结构；审计中没有得到足够支持、完全新的治疗技术。这个结果意味着“技能演化”更接近积累和细化实践策略，而不是让模型凭空发明临床疗法。

### 4.3 论文方法的安全含义

论文的技能演化是高风险环节：如果把一次偶然的迎合、事实泄漏或评分器漏洞保存成技能，后续模型会反复放大它。因此合理实现必须有安全门、来源证据、重复回放、专家审核、版本晋升和回滚；自动把 LLM judge 的高分转成永久技能并不等于实现论文意图。

## 5. Reinforced Internalization Engine（RIE）

### 5.1 会谈级 best-of-N

RIE 在一个固定会谈起点上并行生成多个**完整会谈**候选，而不是只为某一轮生成多个句子。每条候选都沿着自己的对话反馈继续生成，直到会谈结束。之后用 LLM judge 按咨询师侧和来访者侧的 PsychEval 维度评估。

赢家选择的核心约束是：

- 当前会谈的候选共享会前状态；
- 奖励在完整会谈完成后计算；
- 最高 reward 的候选胜出；
- 下一场的记忆、画像和计划只从赢家更新；
- 落选候选可以保存为审计/训练数据，但不能污染正式历史。

公开代码的固定提交对这一部分的实现是每 session 的 `rollout_n=8`，同一 case 的 session 仍然串行，候选只在当前 session 内并发。它不是把 8 条完整长期疗程一直保留到最后，也不是每一轮只选一句回复。

### 5.2 RFT 的目标

论文式（6）可写为：

\[
\mathcal L_{RFT}=-\sum_{t=1}^{T}
\log P_\theta(S_t^*\mid\mathcal H_{t-1}^*),
\]

其中 (S_t^*) 是胜出的会谈步骤，\(\mathcal H_{t-1}^*\) 是它之前的历史。低 reward 候选被拒绝，因而没有进入这个最大似然目标；论文不是用显式的 chosen/rejected margin 来训练。

这也解释了为什么“已经有 RFT 选优”与“已经完成 RFT 训练”是两件事。前者产生数据和排序，后者需要训练样本打包、角色/历史 mask、tokenizer、优化器、checkpoint 和独立验证。

## 6. 论文实验与结果

论文用 PsychEval 做多流派、多会谈评测。可核实的配置包括：每种治疗流派 120 个训练画像、20 个评测画像；Qwen3-32B；32,768 token 上下文；每场 8 个 rollout；bf16、ZeRO-3；3 个训练 epoch；16 张 H200 GPU。

四个主指标是 Counselor Shared、Counselor Specific、Client Shared、Client Specific。Qwen3-32B 版本报告：

| 系统 | Counselor Shared | Counselor Specific | Client Shared | Client Specific |
|---|---:|---:|---:|---:|
| PsychAgent-Qwen3-8B | 7.35 | 7.78 | 5.94 | 8.19 |
| PsychAgent-Qwen3-32B | **7.32** | **7.91** | **5.92** | **8.24** |

这些是 benchmark 聚合分数，不是治疗有效性或现实临床结局。

论文消融表（Table 3）如下：

| 配置 | Counselor Shared | Counselor Specific | Client Shared | Client Specific |
|---|---:|---:|---:|---:|
| PsychAgent | 7.32 | 7.91 | 5.92 | 8.24 |
| 去掉 MAPE | 7.07 | 7.66 | 5.86 | 8.03 |
| 去掉 SEE | 7.02 | 7.52 | 5.61 | 7.90 |
| 去掉 RIE | 7.05 | 7.67 | 5.67 | 7.89 |

在这组实验里，去掉 SEE 的整体下降最大；这支持“可积累的技能经验”是论文效果的重要来源，但不能把一次消融直接解释成因果临床收益。

人工评估包含 522 段完整评分对话，来自 25 个案例和 188 个案例—会谈单元；两名心理学背景研究生和 Gemini-3 对咨询师的 Ethics、Interaction、Intervention、Perception 以 1–5 分评价。论文报告人—人 QWK 约 0.675，PsychAgent 在人工和 LLM 评审中排名第一。这个一致性是有用的可靠性证据，但仍不是临床验证。

## 7. 公开代码和论文训练的边界

作者公开仓库包含多 session 生成、评测、reward best-of-N、prompt/config 和演示工作台；固定提交 `469f45ef468b968b3fccd1936d7e6a0a574e4c5c` 的 `src/rft` 可复核会谈候选生成、评分、选优和存档。

公开版本明确不能单独复现论文的全部训练闭环：完整论文规模训练资产、完整会谈后技能提取/演化流水线以及端到端技能内化训练方案没有随公开仓库提供。公开 RFT 代码更准确的称呼是“session-level best-of-N 数据生成和选优器”，不能仅因为目录叫 `rft` 就说它包含了 optimizer、反向传播和权重更新。

## 8. 当前 psych_sandbox 已经做到什么

### 已经相当接近运行时结构的部分

- **纵向案例和记忆**：当前有四字段 `SessionMemory`（已知背景、会谈回顾、上轮作业、事项清单），并由 E.7 信息提取、E.8 门控合并、E.9 临床摘要和 `MemoryConsolidator` 维护。
- **会前规划和会后再规划**：按流派/阶段生成计划；会后由咨询师自评目标和证据，再结合纵向进度生成下一场计划。
- **分层技能资源**：当前有 BT、CBT、HET、PDT、PMT 五个独立技能树，共 677 个元技能、4481 个原子技能；按流派、阶段、审核状态过滤，超量时才向量筛选。
- **会谈级 RFT 选优**：可选的候选隔离、完整会谈生成、PsychEval 量表评分、安全/披露门控、去重、补采和只让胜者进入正式轨迹，已经覆盖 RIE 的运行时骨架。
- **安全和信息权限**：咨询师只能读已披露证据和允许记忆；来访者模拟器把私有状态规划和受限语言生成分开，并有事实授权、台词证据核验和提前泄漏检查。这是当前项目有意加强的工程约束。
- **评测分层**：RFT 中的 session 评分只用于候选排名；完整轨迹结束后才运行一次 `PsychEvalSupervisor` 整体督导，且分数不回灌计划。这符合本项目的运行时不变量。
- **经验和版本骨架**：已有安全门控的 `ExperiencePool`，以及 `candidate → replayed → expert_reviewed → approved → promoted/deprecated/rolled_back` 的 `SkillEvolutionManager` 状态机。

### 只能算部分实现的部分

- **MAPE 是运行时等价物，不是论文式学习模块**。当前记忆、规划和回复主要通过 API 提示词、结构化 schema 和规则门控实现；没有针对 `D_mem/D_plan/D_resp` 的 SFT 数据集、训练器和模型 checkpoint。
- **RIE 的 N 和口径不同**。当前默认 RFT 候选数为 3，论文实验为 8；当前有更严格的安全资格门和失败留档，reward 聚合、评分模型和温度配置也不应直接宣称与论文完全相同。当前代码明确把候选评分和最终整体督导分开。
- **技能目录不是技能演化**。当前 selector 会从静态资产中选技能并记录公开适用证据；保留树路径不等于从成功轨迹抽取、去重、合并和发布新原子技能。
- **当前来访者模拟借鉴 PatientAct-style 机制**。它增加了渐进披露、信任门控、情绪/行为/阻抗决策和事实证据核验，但这属于来访者仿真增强，不是 PsychAgent 的 SEE 或 RFT 训练本身。

### 明确缺失的部分

1. 从高 reward 胜出会谈自动抽取结构化原子技能（目标、适用前提、步骤、禁用条件、证据来源、适用流派/阶段）。
2. 在同一流派/阶段内做技能新颖性和相似性判断，自动决定 append 或 merge，并把结果写入可审计版本库。
3. 将“胜出候选 → 技能候选 → 回放 → 专家审核 → 批准/晋升”接成真实流水线；目前状态机只是接口和约束。
4. 为 `D_mem`、`D_plan`、`D_resp`、`D_skill` 构建完整训练样本。当前 `training/export.py` 的 SFT 导出只取相邻消息，DPO 导出只取末次咨询师回复，既没有完整历史/计划/技能上下文，也不是论文式 session-level RFT 样本。
5. 训练适配器和参数更新：至少需要 tokenizer、角色和历史 mask、梯度累积、LoRA/QLoRA 或全参训练、checkpoint、恢复和离线验证。`pyproject.toml` 有可选 `transformers/datasets/peft/trl` 依赖，但“声明依赖”不等于已有训练闭环。
6. 与论文配置相称的对照实验：固定 PsychEval 切分、基线模型、候选数、seed、成本/延迟记录、自动评测和独立人工复核。目前文档明确三随机种子、30 案例和人工评审仍未完成。

## 9. 建议的实现顺序

### P0：先定目标和数据契约

不要先改模型。先定义一个可版本化的 `SelectedSessionArtifact`，至少保存：会前记忆、计划、阶段、技能候选/实际技能、完整可见对话、会后记忆、reward 各分量、安全门结果、模型/提示词/数据版本和来源证据。候选和胜出轨迹必须分开；只有胜出轨迹能更新正式记忆，落选轨迹只能进入隔离经验库。

同时把所有评分区分为三类：RFT 排名 reward、最终整体督导分、人工独立评测分。不要把同一个 judge 既当训练标签又当独立实验结论。

### P1：补齐可训练的数据生成

从已保存的正式胜出会谈和审核通过的候选中生成四类样本：

- 记忆抽取：对话 → 证据约束的画像更新/摘要；
- 会前规划：记忆 + 当前案例状态 → 阶段/目标；
- 回复生成：允许记忆 + 当前来访者话语 + 计划 + 选定技能 → 咨询师回复；
- 技能提取/管理：高 reward 会谈 → 原子技能候选和 append/merge 决策。

每条样本必须带 provenance 和安全状态。训练打包时只让应训练的角色输出计算 loss，避免把来访者、审计字段或私有档案意外学进咨询师模型。RFT 样本要保留完整 session 上下文，而不是只导出最后一句。

### P2：先做“影子模式”的 SEE

技能演化先不直接修改生产树：

1. 只接受通过安全/披露门、最低独立质量阈值和重复回放的胜出轨迹；
2. LLM 提取原子技能，程序校验 schema、流派/阶段归属和来源引用；
3. 向量相似性只用于候选近邻，最终 append/merge 需要可审计理由；
4. 新技能进入 `candidate`，不能自动进入咨询师默认目录；
5. 专家审核、固定回放集和回归测试通过后才 `approved/promoted`；
6. 任一安全、泄漏或主指标回退都能回滚到旧版本。

先以离线影子结果统计“新颖但非重复”的比例、合并准确率、技能污染率和跨流派串用率，再决定是否允许在线写入。

### P3：小模型先验证 SFT/RFT

不建议一开始复制论文的 32B + 16 H200 配置。先用 3B/4B 模型和 QLoRA 验证：

- 只训练 MAPE 三任务是否改善跨 session 记忆和目标跟踪；
- 加入 SEE 样本是否改善技能适用性和技能复用；
- 加入 session-level rejection fine-tuning 是否优于单候选 baseline；
- 安全/披露门控是否在训练后仍保持。

只有这些消融有效，才有理由扩大模型、候选数和训练资源。当前项目的 API-only 生产边界可以保留；训练是离线实验管线，不应把本地 checkpoint 或确定性测试网关混进生产仿真。

### P4：独立评测和成本审计

至少完成固定案例集、多 seed、单候选 vs best-of-N、无 MAPE/无 SEE/无 RIE 的消融，并报告均值、标准差、置信区间、失败率、泄漏率、单 session 成本和延迟。人工评测应使用与训练 judge 不同的评审输入和盲法，报告评审者间一致性。自动分数上升但人工真实感下降时，应以人工和安全结果为优先信号。

## 10. 不建议的“捷径”

- **把完整私有来访者档案直接塞给咨询师**：这会破坏当前项目的信息权限和泄漏测试，也不是达到 PsychAgent 论文效果的必要条件。
- **把最终整体督导分数直接喂回下一场计划**：当前项目明确把整体督导设为轨迹结束后的单次评估；改变它会混淆规划和评估，并造成评测泄漏。
- **把所有落选候选当作 DPO 负例**：论文 RFT 是拒绝采样后的胜出轨迹似然目标；落选可能只是评分噪声、模型失败或安全不合格，不能无条件当成反例。
- **让一次高分自动发布新技能**：judge 可能被讨好、突然康复、过度披露或文本风格操纵；技能必须经过证据约束、回放和专家审核。
- **用当前 500 项离线测试证明模型效果**：这些测试验证控制流和权限边界，不调用真实模型，不能证明 PsychAgent 分数或现实咨询质量。

## 11. 结论

如果目标是“像 PsychAgent 一样运行”，当前项目已覆盖记忆、规划、分层技能、来访者模拟、会谈级候选选优和安全隔离的大部分运行时基础；主要差距是默认参数、评分口径和真实 API/人工实验。

如果目标是“获得 PsychAgent 的自演化效果”，最关键的三项工作是：**把胜出会谈打包为完整训练样本；把高质量经验提炼、合并并审核成可版本化原子技能；真正运行 SFT/RFT 参数更新并用独立实验验证**。当前的 `ExperiencePool`、`SkillEvolutionManager` 和 `training/export.py` 是可以复用的骨架，但还不能称为论文闭环。
