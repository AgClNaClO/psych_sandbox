## 1. 当前基线与可改进点

当前流程为：公开证据、允许记忆、目标和风险 → Planner 从当前流派/阶段的末级元技能目录中选最多 3 个 ID → SkillCatalog 精确展开这些组下全部可用微技能 → Actor 选择实际使用的技能并回复。

- 当前已有“不查技能”和“不使用技能”的出口；不能把增加这些出口说成新能力。
- 当前已有会后自评、下一会谈目标和策略更新；不能把增加普通会后反思说成新能力。
- 元技能候选只有名称、描述等信息，微技能使用时机和触发线索要在选组后才进入 Actor 输入。可能出现相关组被提前排除，但本文没有测量发生率。
- 本轮选择主流程只有一次查询 Observation，没有在语义候选不合适时返回 Planner 重新选组的正常循环；网络/格式重试不等于语义重查。
- ID 校验确认“技能来自允许候选”，不能确认“满足使用条件”或“回复实际体现了这个技能”。
- AtomicSkill 定义了 contraindications，但 PsychAgent assets 加载路径没有为现有资源补充这项内容。空列表不代表临床上没有限制。

各库的瓶颈也不同。按现有父子关系离线统计直接子技能数：

| 库 | 可选末级元技能组 | 每组微技能中位数 | 单组最大微技能数 | 更可能的瓶颈 |
|---|---:|---:|---:|---|
| CBT stage1 | 22 | 26 | 43 | 展开后的微技能输入较长 |
| CBT stage3 | 11 | 18 | 46 | 展开后的微技能输入较长 |
| BT stage1 | 41 | 10 | 20 | 选组与展开均需关注 |
| PDT stage2 | 112 | 5 | 17 | 末级元技能粗筛更困难 |

这说明不能只用全库规模选算法：B 更值得先在 CBT stage1/3 验证，C 更适合检查 PDT stage2 的跨组漏召回。统计描述数据形状，不代表这些库已经发生相应错误。

## 2. 方案总览

| 方案 | 主要问题 | 是否引入程序相关性排序 | 成本与成熟条件 |
|---|---|---|---|
| A 技能卡与适用条件核对 | 只凭类别名称匹配、条件未知时仍选技能 | 否 | 低至中；需要审核卡片内容 |
| B PsychAgent 式微技能精筛 | 展开后候选过多、当前话语与技能未充分匹配 | 是 | 中；需要一致的向量模型与索引 |
| C 多路召回与重排 | 元技能粗筛漏掉跨组的适用微技能 | 是 | 中至高；需要召回和重排评测 |
| D 有限次数的纠错查询 | 首次候选不合适后无法再选其他组 | 否，可继续模型选 ID | 中；需要校准重查与停止条件 |
| E 多个技能方案的独立评审 | 单次选择缺少备选比较，技能与回复脱节 | 否，可保持目录精确查询 | 中至高；增加模型调用和评审偏差 |
| F 经审核的技能使用经验 | 忽略相似情境的成功条件和失败教训 | 最小版否；后续经验检索可选 | 需要高质量经验与严格数据划分 |

B/C 改变当前“不使用 BM25/向量匹配”的基线约定，应作为明确的实验变体，不能以“优化目录查询”的名义悄悄加入。A/D/E 可保留模型选择 ID、程序精确展开的职责。F 应先做单病例的结构化历史；跨病例经验只使用公开、合成或获准脱敏且经审核的数据。

## 3. A：技能卡补全与适用条件核对

这是根据当前代码提出的直接改进，不宣称是某篇论文的原样实现。

### 做法

1. 为末级元技能增加简洁的覆盖范围与适用线索概览，来源于已有子技能，不改成逐层导航。
2. 微技能保留原始 ID、名称、描述、when_to_use、trigger，并补充经审核的前提条件、适用场景、容易混淆的相邻技能、不可据此推断的事实。
3. Planner/Actor 针对拟选技能给出简短结构化证据：已知适用条件、缺失条件、冲突线索，以及采用/先澄清/不用的决定。条件状态应包含“未知”，不能把未发现冲突当作符合条件。
4. 只对可靠、结构化、经审核的约束做程序过滤；模糊临床适用性保留给模型与专业审核。不得让模型凭空生成禁忌并自动当作硬规则。
5. 比较拟用技能是否重复、是否与本轮目标一致；支持多个互补技能，不为增加数量而选。

例：“使用频率记录”已有说明要求目标行为起止可辨、可逐次计数。若公开对话只有“最近状态很差”，条件应标记未知，可先澄清行为，不应仅因主题相关就宣称适用。

### 改动位置与验证

技能元数据/加载、domain/models.py、两个 counselor 模板、结构化输出检查。第一版可以不增加模型调用，只增加少量提示词和输出字段。

验证重点是条件不满足/信息不足场景的误选率、正确澄清率和最终回复体现技能的程度。历史选中的 ID 不能直接充当正确标签。

## 4. B：借鉴 PsychAgent 的“选组后微技能精筛”

### 来源事实

PsychAgent 当前公开代码先按会谈目标粗筛末级元技能，默认 n=20；在微技能候选中，结合目标、对话历史与当前输入改写查询，用向量相似度选择默认 top_k=5，threshold 默认 None。粗筛错误仍可能排除正确微技能。

依据：[官方技能管理器](https://github.com/ECNU-ICALK/PsychAgent/blob/main/src/sample/skill_manager.py)，本地同类链路见 [Psych-new](D:/a华东师范/2项目/1实践/Psych-new/src/sample/skill_manager.py:172)。这里引用的是公开实现，不把论文的训练/技能演化能力视为当前项目已经实现。

### 迁移设计

当前 Planner 选组 → 精确展开 → 根据当前输入、公开上下文、本轮目标构造检索问题 → 对微技能向量精筛 → Actor 最终决定。

- 不只嵌入技能名；比较触发条件/使用时机与完整技能说明两种索引文本。
- 保留当前来访者原话与重写查询，减少重写把不确定信息补成事实的风险。
- 根据 token 预算、组大小、验证集表现选择候选数量，允许零结果；不照搬固定 20/5 或任意相似度阈值。
- 索引记录技能文本哈希、向量模型与版本、输入模板与维度。已有 .pt 向量的生成模型身份若无法确认，应重新生成，不能仅因维度相同就与新查询向量混用。
- 新模型依赖按项目运行约定，通过受控网关/服务接入；研究阶段不直接部署或上传病例。

优势：候选较大时降低 Actor 需要处理的材料。风险：相似度衡量语义相关，不保证咨询适用；此方案不能修复选组阶段漏召回。需要比较微技能被错误剪掉的比例。

## 5. C：多路召回与重排，不让元技能成为唯一入口

### 来源事实

ToolLLM/ToolBench 发布了根据任务检索 API 的神经检索器、训练数据和训练脚本。可借鉴“按功能描述召回可用能力”，不迁移其工具执行环境，也不采用其 DFSDT 搜索。

来源：[作者官方 ToolBench 仓库](https://github.com/OpenBMB/ToolBench#training-retriever)、[ToolLLM 论文](https://arxiv.org/abs/2307.16789)。

BGE 官方文档说明：双编码器分别编码查询和候选，交叉编码重排器联合读取二者并打分；常见组合是先召回较多候选，再重排。其分数不是临床安全性或适用概率。

来源：[BGE 重排原理](https://bge-model.com/Introduction/reranker.html)、[支持中文的重排模型文档](https://bge-model.com/tutorial/5_Reranking/5.2.html)。这些是可测试的工具选择，不代表当前中文咨询数据上已经表现更好。

### 迁移设计

在相同流派、阶段、审批与安全约束内，合并三类候选：

1. 当前 Planner 指定组下的技能；
2. 以当前话语、目标、条件检索微技能文本的 BM25/关键词结果；中文分词或字粒度策略需验证；
3. 微技能向量召回结果。

按 ID 去重，使用排名融合或各通道配额形成有上限的候选池，不能直接混加不同量纲的 BM25、余弦和模型评分。再由 LLM 比较适用条件，或用支持中文的交叉编码器初步重排，最后仍由 Actor 判断使用与否。

起始实验可比较 10/20/40 的候选预算；这只是超参数扫描范围。保留跨组检索来源和否决原因，便于定位漏召回。

优势：首次元技能选错时，另一通道仍可能召回合适微技能。风险：候选噪声、重复语义技能、领域重排不可靠，工程成本大于 B。应先影子运行，不影响实际回复，观察新通道究竟补回了什么。

## 6. D：有限次数的纠错查询

### 来源事实

Self-RAG 通过训练的反思标记控制按需检索、内容相关性和生成检查。CRAG 使用检索评估器，按结果质量触发不同纠正动作。两者研究的是生成/问答，不是心理咨询技能选择。

来源：[Self-RAG 官方实现](https://github.com/AkariAsai/self-rag)、[CRAG 论文](https://arxiv.org/html/2401.15884v3)、[CRAG 官方实现](https://github.com/HuskyInSalt/CRAG)。

### 迁移设计

首次 Observation → 检查是否存在满足条件的候选 → 使用候选 / 请求澄清 / 换一批元技能再查 / 不使用技能。

第一版建议仅允许一次额外语义查询，并排除已查过但被拒绝的同一批 ID，保存拒绝原因。需要停机条件与总 token/调用预算。

可以让 Actor 结构化输出“需要重查”分支，避免正常轮次必然增加一次独立评估调用；这要求修改输出 schema 和 counselor 控制流。程序仍只按模型选择的 ID 精确展开，不必增加相似度排序。

与当前不同的是“看到不合适候选之后能够再查询”。当前已经有不查技能、空结果不用技能的出口。

不得声称用一个提示词就复现 Self-RAG 的训练机制。这里仅借鉴反馈控制思路。不得照搬 CRAG 的在线网络补充到咨询运行；纠错查询仍限制在本地批准技能库内。模型自报 confidence 未经校准不能作为可靠概率，宜检查具体缺失证据与验证集上的误拒绝率。

## 7. E：多个技能方案的独立评审

在同一合法候选集合中生成 2–3 个不同的技能使用方案，每个方案包含本轮微观目标、少量技能 ID、简短拟回复。另一个评审调用检查适用条件、公开证据、来访者边界、技能与回复一致性，选一个或全部拒绝；最终仍只展示一条回复。

与“让模型给自己打总分”不同，评审要有明确检查项和证据。不要以文风好、术语多、技能数多为优。可以仅在歧义高或策略冲突的轮次启用。

AutoCBT 的公开实现会将回复草稿与督导意见一起放入后续生成输入，可借鉴“反馈进入修订”的机制：[固定版本生成代码](https://github.com/CAS-SIAT-XinHai/XinHaiAgents/blob/db123ee7caca099ae51aaac0e6e2e71495431ed2/backend/src/xinhai/arena/agents/autocbt.py#L30)。其具体实现核查见 [外部模式笔记](D:/0test/psych_sandbox/notes/skill_selection_external_patterns.md)。本方案的多个技能方案比较是迁移设计，不能声称 AutoCBT 原样实现了技能 best-of-N 选择；可先只做一份方案的一次复核，再测试多个候选。

注意：这是一个拟新增的轮内候选评审，不等于现有轨迹结束后的 PsychEvalSupervisor。后者继续作为外部评测，不能拿测试评分回流指导选择。

优势：直接比较技能使用后会怎样回应，而不只比较技能名。风险：模型调用明显增加、评审与生成共享偏差、重复修改可能使回复机械。需要盲评、候选顺序随机化，以及保持计算预算可比的对照。

不能预设“多反思一次就更准确”。[Huang 等的推理自纠错研究](https://arxiv.org/abs/2310.01798)在其所测模型与推理任务中发现，没有外部反馈的自纠错可能无效甚至退步。该结论不是对当前所有模型或咨询任务的普遍否定，但支持把独立证据、评审标准和对照实验作为必要条件。

## 8. F：经审核的技能使用经验

最小版先记录当前病例的“公开情境—技能—实际回复—来访者明确反馈—后续调整”，让 Planner 看到近期技能使用历史。若来访者明确表示某种做法不适合，后续决策应考虑这条反馈；不能把单次情绪变化简单归因给技能，也不能因技能重复就一律惩罚，连续练习可能合理。

后续只从公开、合成或获准脱敏的案例中构造经审核的正反例，按相似决策情境提供少量示例。经验不能覆盖流派/阶段、安全、隐私和技能审批约束；不在真实来访者上进行未经验证的在线探索。

Reflexion 用语言反馈与反思记忆影响后续尝试，不必更新模型参数；其 ALFWorld 实现按任务维护经验，并把记忆放入行动上下文：[原论文](https://arxiv.org/abs/2303.11366v4)、[固定版本记忆注入代码](https://github.com/noahshinn/reflexion/blob/218cf0ef1df84b05ce379dd4a8e47f17766733a0/alfworld_runs/env_history.py#L38)。详细机制与限制见 [外部模式笔记](D:/0test/psych_sandbox/notes/skill_selection_external_patterns.md)。同病例反馈记忆较接近该参考实现，跨病例示例检索是额外设计，不能由它直接推出有效。与当前普通会后自评不同，本方案强调技能级的证据记录、相似情境对照和跨案例审核。

风险：历史轨迹并非天然正确、成功归因错误、评审偏差循环放大、跨病例隐私泄漏。经验库和测试集必须按病例/来源分离；不把 held-out 测试结果追加回经验库后继续报告同一测试集提升。

## 9. 推荐顺序与实验要求

1. 建立小型选技评测集并冻结当前基线，然后做 A。
2. 做 D，针对候选错误、条件不足、当前无适用技能的情境验证恢复能力。
3. 如果实际发现 Actor 候选过长，比较 B；如果主要问题是粗筛漏掉相关技能，优先比较 C。它们不是必须串行上线。
4. E 用于困难情境或离线评审；F 在有审核经验后推进。不要一次把所有机制叠上去后只报告一个总分。

建议首轮使用 50–100 个公开/合成/批准脱敏的固定对话片段，覆盖五流派和三阶段，按“单一合适技能、多种合理选择、候选缺失、前提不明、拒绝/边界、重复无效、风险绕过”等情境分层。样本数仅用于探索，不足以证明临床疗效。

每条由独立评审标注“可接受技能集合”“不宜使用技能集合”和是否应澄清/不用技能，避免假定只有一个正确 ID。

固定模型版本、技能版本、公开上下文、随机参数和输入；可变方案既报告质量优先结果，也报告相同 token/调用预算下的结果。检索改动先离线评估召回，随后再评估回复，最后做多轮轨迹评估。

指标至少包含：

- 候选覆盖：可接受技能能否进入候选池；专家标注不完整时说明 Recall 的限制。
- 最终适用性：实际选中技能是否满足条件，是否需要澄清却直接干预。
- 回复忠实性：选中的技能是否真正体现在回复中，而非只填 ID。
- 不使用技能的准确性与不当干预率。
- 安全/边界回退、公开证据约束、技能 ID 合法性。
- 总 token、各类模型调用、p50/p95 延迟、超时/错误率。
- 人工盲评与分层失败案例，不只使用同一个模型的自评分。

所有实验临时文件和结果遵守现有运行产物约定：测试归 runs/tests，实际实验归 runs/runtime，每次调用独立目录；来源资料与设计说明保留 notes。这里只记录建议，未运行这些实验。
