# 科研 Web 工作台代码质量评估与修复（2026-10-28）

## 结论与范围

检查覆盖 `frontend/src`、`src/psychsandbox/workbench`、安装依赖、启动入口及工作台测试。
已有模块划分合理：任务、人工会谈、事件、投影、技能演化与导出相互分离，工作台与仿真库独立。
但修复前的测试偏重端点返回和空数据，未覆盖真实 Worker 调用、并发取消及非空训练导出，
因此“测试通过”不足以支持原实施文档中完整可用的结论。

本轮优先解决实际执行失败、状态丢失和科研数据失真。保留工作区已有的未提交修改，
没有改动五流派原始技能树、正式仿真评分公式或共享历史运行；未调用付费模型服务。

## 已修复问题

| 严重程度 | 问题与影响 | 修复 |
|---|---|---|
| 高 | Worker 调用 `CounselingSandbox` 缺少必需 `config`，所有自动实验立即失败 | 使用项目配置；增加完整离线 Worker → 仿真 → 落库 → 导出测试 |
| 高 | 人工 Worker 使用空技能目录；用户风险被固定为 LOW | 加载真实项目目录和技能/记忆配置；复用现有输入风险路由，阻止不合格输出落库 |
| 高 | 消息提交与任务入队不在同一事务，重复请求创建重复任务 | 在会谈事务中入队，按操作 ID 幂等绑定任务；拒绝不同请求复用相同 ID |
| 高 | 手动解锁后旧模型结果仍可写回，甚至覆盖取消状态 | 回复、整理步骤及最终提交核验操作状态和执行标记；解锁取消关联任务 |
| 高 | 关闭会谈缺少互斥/状态检查，失败停在 closing，无重试入口 | 统一检查会谈状态与活跃操作，失败标记 close_failed，前端可重试并复用已完成步骤 |
| 高 | 新会谈可绕过上一场闭环；缺失会谈开场导致 Worker 崩溃 | 原子检查连续会谈边界、前场关闭状态与目标存在性 |
| 高 | 前端监听 jobs，Worker 发布 job:id；停止/取消事件未注册 | 订阅实际任务通道，补齐事件类型、重放去重与断线指示 |
| 高 | SSE 内存消息可越过未读取的历史分页，线程通知也不安全 | 以持久化有序分页作为唯一来源，异步线程读取，不跳过事件 |
| 高 | SFT 使用过时字段而导出空结果；去掉当前用户输入并读取会后记忆 | 使用正式消息列表、当前规划字段与会前记忆；明确上下文为重建结果 |
| 高 | DPO 不兼容真实候选 schema，并尝试拼接两个分支末句 | 校验已提交批次与安全/资格门，只配对相同前缀后的第一条不同咨询师回复 |
| 高 | 导出文件名允许越界写入，同名导出覆盖历史；未经脱敏却标记已脱敏 | 校验跨平台普通文件名，按次建立产物目录，准确标记 anonymized=false |
| 中 | 任务重试缺少持久运行编号，可能新建另一次实验 | 在运行首次进度通知、模型调用前绑定编号，重试恢复同一运行；拒绝失效 attempt 的完成事件 |
| 中 | 督导零分被当作缺失；评测大盘未读 counselor_overall，且把督导分复制成自动分 | 按非 None 取值，使用真实报告字段，无独立自动指标时显示未知 |
| 中 | 无文本评语时自动声明“临床规范符合预期” | 仅生成客观量表摘要，不推断临床结论 |
| 中 | 切换疗程/会谈/流派时旧请求覆盖新状态，版本可能回退；重试新建消息 ID | 增加请求与选择校验、稳定回调和版本同步；仅重试版本冲突并保留原请求 ID |
| 中 | 不可执行任务、错误 lane、非法疗法/参数到 Worker 才失败 | 请求契约前置校验，返回可理解的 4xx |
| 中 | FastAPI / Uvicorn / HTTPX 没有声明在安装依赖中；reload 参数无效 | 补齐运行/开发依赖；通过 Uvicorn 工厂入口传递 reload |
| 中 | 允许任意跨站来源访问本地服务 | 限定开发 CORS 来源，并拦截来自其他页面的跨站写请求 |

另修正前端 PMT 名称、零成本/零延迟显示及 Hook/lint 告警。

## 验证方式与限制

回归测试使用临时数据库、按次测试产物和 `tests/deterministic_gateway.py`，
覆盖真实 Worker 构造、事件跨页、原子回滚、重复请求、取消后的迟到回复、整理失败恢复、
训练导出的真实字段、共同前缀、未来信息隔离、非法路径与跨站写入。

前端使用 Node 内置测试覆盖 HTTP 错误类型、409 分类及 SSE 生命周期；
`npm --prefix frontend run build` 同时完成 TypeScript 检查并更新后端托管的生产静态资源。

原全库基线为 547 passed / 1 failed：启动脚本的用户可调 logprob 开关为 0，旧测试硬编码为 1。
本轮保留脚本设置，将测试改为验证 0/1 设置合法且确实连接命令行开关，未修改评分计算或降级行为。
最终验证结果见 [实施状态](implementation-status.md)。

这轮验证不包含真实供应商接口、付费模型效果、人工浏览器全流程验收或临床有效性评价。
前端仍有较大的组件和宽泛 `any` 类型；后续适合拆分状态与展示，并增加浏览器层端到端测试。
本地研究工作台没有新增多用户身份认证，不应据此推断其适合开放公网服务。
单轮 DPO 偏好来自完整会谈的排序，已标注来源，不能当作独立单轮疗效标签。
