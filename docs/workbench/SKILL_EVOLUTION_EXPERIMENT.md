# 技能进化独立试验

借鉴 PsychAgent 论文 3.2 的定向提取、同元技能分支语义查重和 Append/Merge 管理，并增加 Skip；与完整论文方法的差距见 [研究对照](../research/psychagent_paper_and_project_gap_2026-10-11.md)。
使用现有模型 API 和结构化提示词，不包含论文专门的 SFT 或 3.3 权重训练。

实现核对：2026-11-10。独立试验已经提供提取、快照和对比入口；正式技能发布仍使用原有专家审核流程。

## 启用和使用

停止本项目已有工作台进程后，统一运行根目录 `run_workbench.bat`。
脚本配置区设置 `PSYCHSANDBOX_SKILL_EXPERIMENT=1`，并传递给后台 Worker 和 Web 服务；如需关闭，改为 `0` 后重新启动工作台。
手动启动后端时，也可在 PowerShell 中设置该变量。未设置开关时实验 API 拒绝业务操作，也不创建实验目录。

```powershell
$env:PSYCHSANDBOX_SKILL_EXPERIMENT = '1'
.\.venv\Scripts\python.exe -B -m psychsandbox.workbench.server --host 127.0.0.1 --port 8000
```

`GET /api/skill-experiments/status` 可读取启用状态；其他试验业务接口在关闭时返回 403。试验任务由 API 启动独立子进程，普通 long/short Worker 不认领这些任务。

1. 在 Web 顶部选择“进化试验”，选择一场已提交会谈并创建独立实验。
2. 点击“提取技能”，后台独立进程选择有证据的末级元技能、提取原子技能，并在同流派、同阶段、同分支做 embedding 召回。
3. 查看新增/合并/跳过理由、来源原话、相近技能与前后定义。相似度不是疗效分。
4. 保存实验快照，右侧技能树高亮新增或修改项。可切换历史版本或恢复实验基线。
5. 选择来源对话中一条来访者发言，执行固定上下文的基线/实验版单轮对比。页面展示候选目录、实际选中技能和公开证据，明确区分进入库、进入候选和被选中。
6. 可选运行两组独立完整模拟：相同病例、种子和配置，各自生成新轨迹和整体督导。此操作消耗 API 调用；不会拼接历史台词，也不把单次差异宣称为疗效提升。

默认种子为 42，完整模拟默认 1 场、每场 8 轮上限，允许 1–3 场、每场 1–50 轮，沿用当前项目的 RFT 和评分设置。
固定上下文对比沿用当前生成温度与选技链，两组上下文相同，但不承诺供应商输出确定。
缺少历史会前记忆时使用空记忆并明确标记；这不等于精确重现历史模型输入。

## 隔离边界

- 试验经独立 API 路由、页面和子进程复用正式模拟器与 Planner/Actor；复用保持现有技能选择顺序、记忆、RFT 和评分语义，试验任务与版本不写入正式任务或发布表。
- 正式仿真数据库使用 SQLite `mode=ro` 读取，只导入已经提交的会谈；不读取落选候选、完整病例画像、初末模拟状态或私有规划。
- 来源保留对话、会谈目标和允许的会前记忆。证据必须能逐字匹配来访者台词。普通会谈标为探索经验，不能自动称作高奖励经验。
- 提取输入给每条消息显式标记 `message_index`，与会谈轮次分开。若引用原话准确但编号错误，只在唯一匹配来访者消息时重新定位并记录校正；概述、拼接、咨询师台词和无法定位的重复引用仍拒绝。各提取步骤的语义校验最多纠错一次，不改变正式 Planner/Actor 的查询规则。
- 每次实验在 `runs/runtime/<时间>__skill-experiment__exp-<编号>/` 保存独立 `experiment.sqlite3`、`run.json`、任务日志和诊断。
- 基线复制当前只读资产树，保存哈希；实验不继承或更改正式活动发布指针。各版本记录父版本和独立内容哈希。
- 新技能与合并技能在持久快照中标为 `candidate`，来源为 `experimental-unreviewed`。仅实验专用的内存 registry 暂时允许正常选技链测试这些候选；这不代表专家批准或正式晋升。
- 原始资产、正式数据库、正式发布和历史记录不写入。完整模拟数据库及轨迹分别位于任务目录的 `baseline/`、`experimental/`，临时环境只在子进程内变化。
- 合并不能改变流派或父元技能，不删除已有禁忌。首期拒绝修改跨阶段共用节点，避免隐式影响另一阶段。

## 持久化和失败

离开或刷新页面后可恢复实验和任务状态。每个实验同一时间只接受一个任务，SQLite 事务保护文档更新。
执行进程持有实验目录和任务目录的 OS 锁。失败记录保留进度与诊断，不保存成功候选或自动生成版本。
提取任务的 `diagnostics/extraction-<schema>-<attempt>.json` 保存结构化输出、语义拒绝原因和证据定位校正；页面显示具体失败阶段，模型接口原始异常仍只留后端日志。
“检查中断任务”只处理创建超过一分钟且任务 OS 锁已经释放的记录，不停止仍存活的任务。
中断或失败后可重新发起操作，使用新的任务编号；部分模拟轨迹保留审计，不当作完整对比。
保存快照只能使用服务端生成的候选，同一候选不能重复应用。保存和切换版本均只影响该实验。

当前页面展示的是机制试验，不自动脱敏或发布，不提供正式专家审批入口。
需要正式发布时应另行完成原有专家审核流程，不能将实验状态当作批准结果。

本试验的提取进度与任务记录保存在实验文档中；自动实验台的 `simulation_status` 属于另一任务通道。切换页面或看到试验完成，不表示正式活动技能版本已经改变。验证边界与后续评测见 [研究路线](../ROADMAP.md)。
