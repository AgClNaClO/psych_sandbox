## 合理的后续转换方案

### 分离四种信息，不改变现有双角色权限

| 信息 | 存放及用途 | 禁止用途 |
|---|---|---|
| 原文事实 | evidence_nodes；来源文件、JSON 路径、起止位置、原文及哈希 | 将标点、解释或治疗建议作为来访者事实 |
| 理论概念化 | 分流派的 theory 与带出处的 5Ps 投影；标注直接事实/结构映射/待核实 | 把治疗师推断自动当作来访者的自知或已披露内容 |
| 模拟假设 | 信任层级、情绪成本、初始状态、表达调节单独版本化 | 宣称这些数字是原数据测量值或因果机制 |
| 参考轨迹及策略 | 独立研究/离线评测资产 | 将未来会谈结论、参考台词灌入当前咨询师或模拟器 |

当前来访者发言器已主要接收本轮授权事实、已说记忆、状态和表达指令；应保留这种限制，而不是为“更像真人”开放全部私有画像。咨询师继续只读公开证据和允许记忆；内部安全审计、未披露事实与候选分数不进入咨询师记忆。

### 建议按以下顺序实施，属于后续方案而非本次已完成工作

1. **建立完整转换验收报告。** 检查原文切片一致性、重复事实、否定与时间限定保留、依赖图无悬空引用/环、来源覆盖率、字段分类正确性。`needs_review` 应有明确的隔离/复核策略，不能只记录一个布尔值就按已确认事实投喂。原文保留不变，清理报告独立保存。
2. **版本化模拟假设。** 当前 `_initial_state` 按关键词把 valence、arousal、distress 等映射到固定值；这只能算工程先验。保存参数来源、规则版本与不确定性，在小样本比较默认值、区间采样和消融结果。不要一次大幅改写全部人设，避免无法归因。
3. **把披露判定从全文子串升级为证据事件。** 记录事实 ID、已披露片段、发言者、原话及顺序。区分“提问/假设/称呼”和“断言”，处理改述、否定与短属性歧义。不要简单忽略所有单字：本次 HET-030 的性别称呼有依据继续拦截。语义判定可能新增 API 成本及误判，先用离线标注集比较再决定是否上线。
4. **防止参考信息和评估泄漏。** 审计初始全局计划是否含未披露细节或未来结果；开场只保留可允许的阶段目标，后续由咨询师自评和纵向信息形成。训练/验证/测试按来源病例及近重复簇划分，不能随机拆同一病例的会谈。候选排序量表与最终评价高度重叠，应补独立盲评，防止仅优化裁判偏好。
5. **增加会后分阶段恢复。** E.7、E.8、E.9、自评、下一计划分别用输入指纹及输出校验记录完成状态；只在输入和模型配置相同的前提下复用。正式会谈仍一次事务提交，禁止失败分支污染记忆。优先计量每阶段调用数、token 和耗时，避免缓存设计复杂度高于实际节省。

建议验收：先回放本次四个失败，再抽取五流派样本进行人工来源核验，最后比较新旧转换下的拒绝率、披露错误率、参考事实泄漏、摘要失败率、重复调用数与成本。成功完成运行不代表咨询质量有效，RFT 分数提高也不自动证明临床收益。
