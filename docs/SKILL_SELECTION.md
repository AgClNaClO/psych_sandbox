# 当前技能选择流程

适用于 `evidence_vector_retry_v2`。原始 `assets/skills/sect` 的节点、父子关系、JSON 和 `.pt`
均保持不变；不逐层选择，不读取原有 `.pt` 向量缓存。

## 1. 元技能提示和原子技能信息

`SkillCatalog.available_meta()` 仍只提供当前流派、阶段内有已批准原子技能的末级元技能。
为每组动态增加 `selection_hint`（最多 180 字）：可用原子技能数、最多三个范围示例、
使用时机的原文节选（缺少时退到触发词）。只统计当前可用子技能，不混入其他阶段或未批准技能。
示例不是穷举，也不是新的临床适用规则；原有元技能名称和描述保留。

`SkillRegistry` 为原子技能新增的信息只有 `paths`：按阶段保存“流派目录 / 阶段目录 /
全部祖先名称与原始 ID / 原子技能名称与 ID”。不增加原文摘要字段；原有完整 `description`、
使用时机和触发条件保留。

例如 BT 253 的概念化阶段路径为：

```text
bt / stage1 / 评估性会谈 [285] / 行为的观察与记录 [148] / 行为记录 [151] / 使用频率记录（连续记录法） [253]
```

信息只在内存和运行记录中出现，不回写资源。兼容旧 JSON：新字段可缺省；仅当旧来源没有原始
祖先链时，路径退为流派、阶段、直接元技能和原子技能，不虚构未知祖先。

## 2. 选择必须有依据

Planner 使用 `prompts/counselor/planner_system.jinja2`，最多选择三个组，并为每组返回
`selection_evidence`。Actor 使用 `prompts/counselor/actor_system.jinja2`，为真正选用的原子技能
返回 `decision.skill_evidence`。每条证据都是：

| 字段 | 内容 |
|---|---|
| `skill_id` | 被选择的元技能或原子技能 ID |
| `evidence_quote` | 2–160 字的公开原文 |
| `reason` | 1–160 字的适用理由 |

程序校验引用是否来自当前或近期来访者话语、已解锁档案内容、允许的摘要/目标/未解决问题/
会后反馈，忽略空白和英文大小写差异。技能描述、咨询师的问题、未披露的私密档案均不能替代
来访者证据。无有效引用的 ID 会被移除并记录警告。

这只能检查证据出处，不能证明理由在临床上成立。模型仍须核对使用时机和触发条件；未知前提
应先澄清。向量相似度也不是适用概率或疗效证据。

## 3. 候选过多才调用向量接口

顺序为：风险/边界检查 → 流派/阶段/批准状态过滤 → Planner 选组及证据校验 → 精确展开 →
条件向量筛选 → Actor 核对适用性并回复。目录本身仍是精确 ID 查询。

`configs/runtime.yaml` 中：

```yaml
skill_selection:
  vector_threshold: 24
  vector_top_k: 12
```

CLI 通过 `default_config(root)` 读取这个 YAML，再应用显式命令行覆盖；直接构造 `SandboxConfig`
的 Python 调用则使用模型默认值，或调用者传入的配置。

只有展开数量 **大于** `vector_threshold` 才调用 embedding；等于或低于阈值全部返回。
超过时按余弦相似度保留 `vector_top_k` 项，再由 Actor 决定是否使用。`top_k` 必须为正且不超过阈值。
这些数值是初始工程预算，尚未经过效果调优。

默认使用 ChatECNU 的 OpenAI 兼容 embedding 接口。聊天地址为官方
`https://chat.ecnu.edu.cn/open/api/v1` 时，以下三项可留空：

```dotenv
EMBEDDING_MODEL=
EMBEDDING_BASE_URL=
EMBEDDING_API_KEY=
EMBEDDING_TIMEOUT_SECONDS=60
```

同一官方端点会自动使用 `ecnu-embedding-small` 和聊天密钥 `MODEL_API_KEY`；显式的 embedding
配置优先。只有 HTTPS、官方主机、443 端口和 `/open/api/v1` 路径匹配时才共用密钥；其他主机、
端口或 API 路径必须独立填写三项，不会将聊天密钥转发过去。不会拿聊天模型名称当向量模型。
配置缺失只在需要向量筛选时明确报错，不会静默改为全量候选。

[ChatECNU 官方文档](https://developer.ecnu.edu.cn/vitepress/llm/api/embedding.html) 给出
`ecnu-embedding-small` 和 `/embeddings` 接口；本次验证的是配置和请求契约，未调用真实 API。
查询向量文本使用当前来访者话语、本轮目标、选组证据、会谈目标、近期来访者消息和最近摘要的
有限节选；技能文本使用路径、说明、使用时机及触发词。上述公开咨询内容将发送到所配置的
embedding 服务；部署时需确认该服务符合数据使用要求。

技能向量仅在本次运行内存中缓存，以接口/模型身份及文本摘要区分；查询向量不缓存，运行开始
时清空缓存。不生成新的散落文件。接口每批最多 64 条，ChatECNU 还按每批总字符数不超过 8192
拆分；单条超限明确报错，不截断内容。检查返回索引、数量、维度和有限非零向量；
异常会使本次运行失败，不冒充成功筛选。

## 4. 一次纠错查询

| 首次结果 | 是否额外查询 |
|---|---|
| 没有合法组或没有公开选组依据，目录为 `invalid_selection` | 是，记录校验原因 |
| Actor 判断 `unsuitable`，并给出具体 `query_rejection_reason` | 是 |
| `suitable`：有适用候选 | 否 |
| `needs_clarification`：尚缺适用前提 | 否，先澄清 |
| `not_needed` 或 Planner 不查询 | 否 |

纠错时将拒绝原因交给 Planner，移除第一次已经展开的所有元技能组，包括向量筛选时未保留的
原子技能所属组。再次请求旧 ID 也会被程序剔除；不能通过换顺序或混入新 ID 重查旧候选。
当前树中每个原子技能归属一个直接元技能组，因此两次实际展开的候选不重叠。

第二次仍不合适就停止查询，Actor 给出支持或澄清回应，不选择不适用技能。正常为两次模型调用
（Planner、Actor）；无效首次选组最多三次；Actor 拒绝后最多四次。网络/JSON 格式重试与技能
纠错预算不同；接口故障不会触发换组查询。安全和来访者边界处理仍优先。

## 5. 查看记录与验证

每轮 `skill_queries` 最多两条，保存规划及引用、展开前候选 ID、筛选后候选 ID、选用 ID、判断、
拒绝原因、校验警告、是否向量筛选、模型名和保留候选分数。最终 `decision` 保存原子选技依据。
这些字段进入 SQLite、`trajectory.jsonl` 和 `result.json`；HTML 的“咨询师可审计规划与决策 → 技能查询记录”
按尝试顺序展示每次明确输出的简短规划摘要、目标、执行计划、查询意图，以及数量变化、判断、拒绝原因
和选技依据，包括重查前被拒绝的规划。这里只展示结构化的决策摘要，不采集或展示模型内部隐藏思维链。
轨迹配置快照记录阈值与 top-k。

产物继续放入 `runs/tests/<测试批次>` 或 `runs/runtime/<运行批次>`，详见 [运行产物](RUN_ARTIFACTS.md)。
旧结果没有这些字段时仍可读取和渲染。

离线测试覆盖树文件不变、完整路径且不携带额外摘要、筛选阈值、余弦排序和缓存、依据/ID 校验、一次纠错、
候选不重复、API 契约以及记录持久化。它们证明流程约束，不证明真实 embedding 召回率或咨询效果。
实际服务配置后仍需在固定案例集上比较候选召回、选择合理性、额外查询率和成本。
