# 会谈候选生成与 RFT 选优

这里的 RFT 是会谈级采样与贪心选优研究模式，不包含权重训练。默认开启；使用 `--no-rft` 或 `--rollouts 1` 关闭。候选数默认 3，生成与评分并发为 null 时跟随候选数，显式 CLI 并发参数用于限流。

截至 2026-11-10，网页也可设置 RFT 开关和 2–32 个候选，并为每场设置 1–50 轮上限。网页续跑和任务重试恢复原轮数与 RFT 设置，评分方法等仍须通过兼容校验；网页新实验草稿不覆盖这些历史参数。

## 分支与提交

每个候选从相同会前案例、计划、记忆和状态的独立副本开始，生成完整会谈；候选各自持有咨询师/来访者对象与技能缓存。保存对话后执行安全/披露资格门、去重与 PsychEval 评分，再按奖励选择赢家，同分按编号选较小者。

生成与评分按候选衔接：完成且通过资格门的候选立即进入评分，其余分支继续生成。量表和子提示并行请求，再按原始目录顺序汇总；生成与评分共享每端点/模型默认 5 个 HTTP 槽位（`MODEL_MAX_CONCURRENCY`），SDK 重试也须获取槽位，退避期间释放。该限制通过 OS 文件锁覆盖同一项目检出的 CLI、Worker 和技能试验进程；不覆盖其他软件或其他检出目录。

相同公开对话只评分一次，首次完成的合格分支提供评分；整批完成后仍将最小编号保留为规范候选，`score_source_index` 标明实际请求及诊断来源，其他重复分支不参与选优。整批全部生成/资格/评分检查结束后才选择赢家；任何后续即时风险取消并等待全部生成、评分退出，不提交已完成评分的分支。

只有赢家执行记忆 E.7/E.8/E.9、咨询师目标自评、纵向阶段判断、下一计划和正式会谈提交。落选分支留在候选审计，`SessionRecord` 不嵌入每场 `SessionEvaluationReport`。完整疗程结束后临床督导仅执行一次；两种评分都不驱动后续计划。

## 量表与条目评分

| 层级 | 共享量表 | 流派专属量表 |
|---|---|---|
| 咨询师 | WAI、HTAIS、RRO、custom_dim | BT MITI；CBT CTRS；HET TES；PDT PSC；PMT EFT-TFS |
| 来访者 | SCL-90、PANAS、RRO、SRS | BT STAI；CBT BDI-II；HET CCT；PDT IPO；PMT SFBT |

默认使用离散条目评分；显式开启 logprob 后使用 `item_logprob_v2`：每个原提示文件一次无约束 JSON 请求，逐 `score` Token 计算概率期望后使用原聚合公式，不另加总体判分。RRO 24 项共用一次请求，反向项为 {2,7,16,17,18,19,24}，再按双方各两个因子汇总；PANAS 先将正负情绪各自映射为0–10均值，再算 `(positive-negative+10)/2`。custom_dim 合并四文件，条目审计键带来源文件，避免重复编号覆盖。

其他量表按自身原始范围映射0–10：1–5、1–7、0–6、0–4、0–3或0–2。症状分保持越高越重，方向在奖励中处理。开启 logprob 时，`item_scores` 保存原范围连续分，`item_logprobs` 保存各项质量、分布、采样分与位置。详见 [评分方法](../notes/logprob_scoring_borrowing.md)。

## 奖励与失败

咨询师量表以绝对分按 PsychAgent 固定均值/标准差做 z-score，并裁剪到[-3,3]。来访者使用相对上一已提交赢家的差值，标准化后对 SCL-90、BDI-II、IPO 反向。所有可用 z 值取算术平均；首场无历史快照时跳过来访者增量。SCL-90 会被报告，但不进入默认 RFT 奖励指标集。固定统计在 `evaluation/rollout.py`，不得按本批候选重新估计。

资格门只决定能否参选，不贡献分数；没有咨询师绝对分下限。即时风险使整批进入 safety_hold，不选赢家。传输错误按 `MODEL_MAX_ATTEMPTS` 重试；JSON/评分失败按既有 `judge_retries` 与 `resample_limit` 处理，仍不足 `min_eligible` 则整批失败。任一必需条目缺失分布、对齐失败或质量不足都明确失败，不用零分、均分或其余条目补齐，不逐项补问。

## 恢复和记录

已选中但尚未提交的会谈可从选优检查点继续会后整合：验证原会前记忆、状态、计划、RFT 配置与奖励基线，并重检安全门；新检查点同时验证病例快照。此路径不重复生成和评分。旧检查点没有病例快照，恢复须保持原实验数据。会后 E.7/E.8/E.9 尚不分别缓存。

候选文件、数据库与运行锁共同保护会谈边界。日志记录候选状态、实际并发和量表步数；重试不重复累计进度。诊断通过 ContextVar 按异步候选隔离。

候选目录内 `request_metrics.jsonl` 分别记录 HTTP 排队、响应、重试间隔与其他开销，并保留每次 SDK/外层 HTTP 尝试的状态；不包含提示正文和密钥。网页在生成与评分重叠时同时显示两组计数，计数不代表已选中或已提交。

CLI 与网页分别呈现生成、候选评分、会后整理和已提交场数。量表完成计数不是评分值，候选轮数的分母是预算上限；提前结束不要求补足到 100%。网页 `simulation_status` 按任务 attempt 和 revision 恢复，失效 Worker 不得覆盖当前尝试；该遥测不参与奖励或下一计划。

新运行保存评分方法及有效温度。旧总体 logprob 方法与新逐条目方法不能共用 RFT 历史奖励基线；恢复检测到方法变化时要求新建运行。已有记录保持可读，旧运行产物不自动重算或迁移。文件约定见 [运行产物](RUN_ARTIFACTS.md)。
