# 向老师汇报发言稿：来访者建模与后续研究

> 展开版主稿约 12—15 分钟；文末备答不计入主稿，无需全部朗读。  
> 基线：`codex/v5plus-client-v4-integration`，2026-09-07。

老师好，我今天主要汇报项目中来访者智能体的具体构建方法、当前完成程度，以及它怎样服务于后续的多智能体沙盒和自进化研究。

当前来访者的构建可以概括为四层：案例画像、披露控制、互动状态和语言生成。案例规定人物背景，状态描述互动变化，披露机制控制信息展开，再由大模型生成回答。我们希望通过这套流程，让人物保持一致、交流自然，并减少信息提前泄漏。

## 一、画像从哪里来，怎样变成可运行对象

项目当前使用固定版本的 PsychEval 数据，覆盖 BT、CBT、HET、PDT、PMT 五个流派，共 341 个案例。原始数据中包括基本资料、主诉、成长经历、咨询需求，以及各流派自己的概念化字段。例如 CBT 有特殊情境、自动思维和应对策略；PDT 有核心冲突、客体关系和反应模式。

数据处理可以分成五步：读取原始字段、切分自由文本、核验来源、组织画像、保存运行缓存。

**第一步，读取原始字段，保留流派差异。** 程序为每个案例建立统一编号，读取 `client_info`，并把原数据中的会谈结构单独整理成计划。姓名、年龄、职业、主诉等字段直接映射；成长经历、语言特征和咨询需求等长文本需要进一步处理。CBT 的自动思维和 PDT 的关系模式仍保留各自的字段语义，不能为了统一格式把它们解释成同一种心理特征。

**第二步，用抽取模型切分自由文本。** 当前转换需要单独配置 `PROFILE_MODEL`。它的任务是从原文中选出连续片段，返回文字、起止位置、类别、激活词和信任档位。例如，一段成长经历里可能同时有事件、情绪和应对方式，可以分开保存。结构化的流派字段主要按规则映射，并不是所有字段都经过模型重新切分。

分类的作用是避免把不同性质的内容混在一起。比如 `language_features` 中，“说话简短”可以作为表达风格；如果还写着某个人物或某段经历，就不能直接当作纯风格传给生成器。`core_demands` 也需要区分“来访者希望改变什么”和“材料建议咨询师使用什么技术”：前者可以成为来访者目标，后者不能自动变成来访者说出口的需求。

**第三步，由程序核验抽取结果。** 模型返回的字符位置可能不准，所以程序会根据片段文字在原文中按顺序重新定位。起点包含、终点不包含；定位时容忍部分全角标点和引号差异。还要检查片段是否按序、不重叠，以及有没有遗漏有意义的文字。模型提供的激活词若不在对应片段里，就会被过滤。这样的校验能确认“文字来自哪里”，但分类和信任档位是否合理仍需要人工判断。

例如，假设原文是“最近工作压力很大。我常常担心犯错。”，可以保留“最近工作压力很大”和“我常常担心犯错”两个连续片段，并记录各自位置。不能把它改写成“因童年批评形成完美主义”，因为新增了原文没有说明的经历和因果关系。这个例子只是说明抽取规则，不是实际案例或模型运行结果。

**第四步，把证据组织成可运行画像。** `EvidenceNode` 保存片段、原文字段路径和字符位置。它的编号由案例编号、路径和位置生成，方便追踪同一来源。`DisclosureItem` 再引用这些证据，增加激活词、信任档位，以及适用时的会谈范围或依赖关系。这里的依赖字段可以为空，并不意味着每个条目都已经人工建立了完整依赖链。

同一组证据还会用于整理 5Ps：主诉描述当前问题，易感因素描述有依据的背景，诱发因素描述触发，维持因素描述持续机制，保护因素描述资源。原文不足时允许为空；不能因为一件事发生在童年，就自动认定它是当前问题的原因。原流派概念化仍单独保留，5Ps 只是跨流派的整理视图。

`InteractionPrior` 则把有来源的应对和关系倾向提供给内部规划器。例如 PDT 资料足够时，可以整理为类似 CCRT 的“愿望—预期他人反应—自我反应”结构；CBT 则可以保留中间信念和应对倾向。纯表达风格另存，约束说话方式。这些整理结果都需要引用已有证据，不能当作新的临床诊断。

**第五步，保存并检查运行缓存。** 当前使用 schema-v4 的 `ClientProfile`。转换先写独立暂存目录，验证画像结构、案例数量和来源等信息后，再替换正式缓存。运行时读取 processed 数据，并检查版本、抽取配置及适用的源摘要，不会在每次咨询开始时重新调用模型处理案例。

抽取校验失败时，程序会尝试修复；最终失败则保留整段原文并标记 `needs_review`，后续由人工复核。需要注意，这个标记并不等于所有相关条目都会自动禁止运行。目前本地缓存清单记录 3100 个抽取项，其中 116 个 fallback/待复核项；这是缓存统计，不代表已经通过人工审核，也不能直接当作病例错误率。

## 二、一次来访者回答是怎样生成的

每一轮分为“披露门控—内部规划—语言生成—核验更新”四步。

第一步，披露门控读取咨询师刚才的话。它先匹配事实的激活词，再检查会谈范围、前置事实和信任档位。如果多个相近事实无法区分，就提示来访者请求澄清。这里决定的是可用事实范围，是否实际说出还要由下一步规划。

第二步，内部状态规划。规划器可以读取完整私有画像，因为它需要维持人物和心理反应的一致性。但它不负责说话，只输出一个结构化 `ClientTurnSignal`，包括主要反应、反应强度、行为类型、阻抗方式、信任变化，以及本轮真正准备使用的事实 ID。当前默认策略是紧凑版 PatientAct，两阶段总共通常调用两次来访者模型：一次规划，一次生成。

第三步，受限语言生成。这个生成器看不到完整画像。它只能看到表达风格、当前状态、最近对话、过去已经说过的内容、本轮规划器选中的获准事实，以及不含正文的 blocked 话题信号。因此，即使私有画像里有一段创伤经历，只要本轮没有通过门控，生成器就拿不到正文。

第四步，确定性核验。模型返回台词和它声称披露的事实 ID。程序会检查台词里是否真的能找到对应证据，同时检查是否出现未授权事实。第一次越界会带着修复指令重试一次；仍然失败就换成与当前行为相符的安全回答。只有实际说出口、并能找到文本证据的片段，才会进入后续记忆。

这套设计分别记录“来访者知道什么”“本轮允许说什么”“实际上说了什么”和“咨询师以后知道什么”，让信息传递可以被检查。不过，规划说明和会后记忆仍可能携带间接信息，后续需要沿实际请求载荷逐项审计。

## 三、情绪和关系状态怎样变化

这部分可以按照“初始状态从哪来、每轮怎样更新、怎样影响回答、下一场怎样继承”来理解。

**首先，初始状态由规则建立。** 当前有情绪效价、唤醒度、痛苦、信任、阻抗、希望和疲劳七个 0–1 数值变量。效价表示情绪偏积极还是偏消极，唤醒度表示激动或紧张程度，两者不同：低落可以是负效价但低唤醒，紧张则可能是负效价而高唤醒。关系破裂另外用“无、正在出现、活跃、修复中”四个离散状态表示。

初始化时，程序检查主诉、咨询需求和病史中的关键词。出现“焦虑、紧张、担心、失眠”等词，会设较高唤醒度；出现“抑郁、低落、无力、疲惫”等词，会设较低效价。这是关键词启发式，不是诊断或量表测量，也可能误读否定句。信任初始为 0.25，阻抗为 0.4，疲劳为 0.1；其他参数随这些简单规则设定。

**其次，每轮先生成互动判断，再进行数值更新。** 披露门控先用本轮开始时的信任值选择候选事实。规划器结合画像、当前状态、咨询师发言和近期对话，判断来访者是感到被理解、产生希望、更加清楚，还是被误解、害怕或受到挑战，并选择行为和信任变化等级。台词生成与核验完成后，程序才更新状态，因此本轮新增加的信任要到下一轮才影响事实准入。

信任有独立的更新通道。模型可以判断轻微上升或下降，再由程序映射为固定增量；普通同理在提示词中通常要求保持不变，不能每听到一句安慰就自动涨信任。例如从 0.38 轻微上升到 0.41 后，下一轮才可能使用阈值为 0.40 的相关事实；还要满足话题匹配等条件，不会把所有达到阈值的事实一次说完。

情绪则通过另一个“进展信号”更新。程序把反应类别映射为数值：感到被理解对应 +0.02，产生希望对应 +0.05，感到被误解对应 −0.06；如果行为是产生洞察或讨论计划，还会增加对应项。这个信号再小幅改变希望、痛苦、效价和唤醒度。它可以为负，所以状态允许恶化；但它来自固定映射，不能称为模型测出了真实心理改善。

阻抗采用逐步靠近目标值的方式。如果本轮行为是阻抗，目标值设为 0.8；其他行为设为 0.25，每轮只向目标移动差值的 8%。例如当前阻抗为 0.4，出现阻抗行为后会变为 0.432，而不是直接跳到 0.8。疲劳每轮增加 0.025，阻抗时再额外增加 0.025，所以当前会谈内疲劳总体只会上升。

关系破裂由单独规则处理。检测到施压词或较大信任下降时，进入活跃状态；已有破裂且检测到尊重边界的表达时，可以进入修复中；修复中再出现信任提升，才可恢复为无破裂。这部分仍含关键词规则，不能把单个词命中等同于完整理解了咨询关系。

**这些状态会怎样影响后续对话？** 信任直接参与事实门控，是明确的代码约束。其他数值主要通过提示词进入规划器和台词生成器，让模型调整语气、合作和探索方式；它们并没有各自对应一套确定性的语言规则。因此，数值发生变化是否真的反映在台词中，还需要检查轨迹。当前还存在低信任下连续探索后的程序回撤，需要评估它会不会造成机械回应。

**最后，跨会谈采取部分保留、部分恢复。** 默认以初始信任为基线，保留上场信任变化的一半。例如初始是 0.25、上场结束是 0.55，下场开始是 0.40，而不是简单把 0.55 除以二。疲劳减少 0.25，但不低于 0.1；阻抗和关系破裂恢复到初始值；效价、唤醒度、痛苦和希望则沿用上场结束值。已经说出的事实继续保留，不会因为信任回落就变成咨询师不知道的秘密。

当前可以准确汇报为“模型判断驱动的规则状态转移”。它便于追踪和回放，但初始化、更新系数和跨会谈重置都需要验证。还有一个实现细节：若台词因泄漏而被替换成安全回答，程序仍按本轮规划信号更新状态，没有重新判断替代回答后的信任。这也是后续要检查的状态与实际台词一致性问题。

## 四、来访者怎样进入多智能体闭环

咨询师不会直接收到完整画像，主要通过对话和跨会谈记忆了解来访者。会谈结束后，系统提取信息、合并历史并生成摘要。不过，当前咨询师还会收到案例计划目标；合并模型也能参考全局画像，程序的回填检查没有覆盖所有嵌套内容。因此这里已经建立了边界控制，但尚不能保证所有路径都没有泄漏。

当前督导师在整条多会谈轨迹结束后做一次整体评分。另有可选的会谈级 RFT：从相同会前状态生成多个完整候选，用安全门槛和 PsychEval 量表评分选出一条，只有赢家进入记忆和下一次会谈。但当前 RFT 是“采样、评分、选优”，不是在线强化学习，也没有在运行过程中更新模型权重。

## 五、目前完成到什么程度

已经完成的是：有来源画像、五流派字段隔离、渐进披露、两阶段来访者生成、台词证据核验、跨会谈记忆、情绪关系状态、完整轨迹和候选会谈选优。

还没有完成的有三项。

第一，五大人格尚未真正接入。代码中虽然保留 `BigFive` 数据类型，但当前案例不会生成人格分数，运行时也不使用它。因此不能说五大人格已经实现。

第二，EFT 尚未成为独立流派。当前的 HET 和 PMT 不能通过改名替代 EFT；EFT-TFS 目前只是一个评估量表名称。真正接入 EFT 需要独立案例、技能树、治疗阶段和评价标准，并经过心理学背景人员复核。

第三，自进化闭环还没有完成。现在有经验池、技能生命周期、SFT/DPO 导出接口和会谈选优，但选优结果还没有自动进入训练，正式 QLoRA、偏好训练和独立测试集验证也没有完成。

## 六、下一阶段研究安排

第一阶段先验证当前基线。复核待审核的抽取项，建立泄漏、虚构、过早披露和机械阻抗测试集；然后使用真实 API 做多案例、多次重复实验，并请至少两名心理学背景评审者评价人物一致性、自然度和披露节奏。还要做无状态、无门控和单阶段生成的消融，证明各模块确实产生增益。

第二阶段加入可验证的人格和情绪模型。五大人格会作为独立的行为条件变量，而不是新案例事实；需要明确它影响的是表达长度、探索倾向、情绪反应还是合作方式。情绪状态则采用“上一状态 + 咨询行为影响 + 个体差异 + 受控扰动”的转移形式，用标注轨迹拟合参数，并检验长期稳定性、可区分性和跨会谈一致性。

第三阶段结合独立 EFT 建设，把审核合格的完整会谈送入经验候选池。先开展监督微调或模仿学习，再分别研究偏好优化与强化学习，拒绝采样用于筛选数据。训练时固定来访者版本，按案例隔离训练和测试，检验提升能否迁移到未见来访者；技能和模型更新经过回放、专家审核、独立评测，并保留回滚机制。

最终目标是形成来访者、多流派咨询师和督导师共同组成的多智能体心理咨询沙盒，使系统形成“咨询—督导—反馈”闭环；再通过经验积累、策略优化和严格验收，实现可审计、可回滚的自进化，而不是只追求生成更像心理咨询的文本。

## 可能被问到的问题与答法

### 1. 为什么不直接把完整画像交给来访者模型？

内部规划器确实需要完整画像来保持一致性，但台词生成器不需要。如果完整画像直接进入语言生成，模型容易在第一次会谈中主动倾倒背景，或者在咨询师未问到时泄漏敏感事实。分离后可以精确记录每轮授权和实际披露。

### 2. 门控会不会让对话很机械？

有这个风险。当前关键词匹配可能漏掉同义问法，候选歧义可能带来重复澄清，固定信任阈值也可能使披露节奏突变。另外，低信任下连续探索后有程序回撤规则。需要统计澄清、拒绝、回退比例，结合人工评审和消融实验决定机制如何改进。

### 3. 五大人格准备怎样获得？

不能从案例 ID 随机生成，也不能仅凭主诉主观推断。可采用两条路径：使用带量表或专家标注的数据；或构造受控合成人格条件用于机制实验。两者都要把“研究条件”与“案例事实”分开，并检验不同人格条件是否产生稳定、可区分但不过度刻板化的行为。

### 4. 当前情绪状态有心理学依据吗？

状态维度借鉴了效价—唤醒、痛苦、希望、联盟信任、阻抗和关系破裂等概念，但当前转移系数是工程启发式，不是已验证参数。后续需要用标注轨迹估计参数，并与简单基线比较预测误差和行为一致性。

### 5. 为什么说 RFT 不是强化学习训练？

因为当前没有策略梯度、价值函数或权重更新。它是在相同初始状态下采样多条完整会谈，再由评分器选赢家，属于推理时 best-of-N/拒绝式选择。它可以产生后续偏好训练数据，但本身不是模型训练。

### 6. 督导师是否已经形成反馈闭环？

当前下一次会谈计划主要来自咨询师会后自评和纵向进度；最终督导评分只做评估。研究“督导反馈是否改善后续策略”需要建立独立实验分支，并和无督导反馈组对照，避免把评估器同时当裁判和训练信号造成循环论证。

### 7. 为什么还没有 EFT？

当前 PsychEval 可运行数据对应 BT、CBT、HET、PDT、PMT。HET 不是 EFT，PMT 中使用 EFT-TFS 指标也不代表有 EFT 咨询师。直接改名会造成理论和数据错配，所以要独立建设并复核。

### 8. 怎样证明来访者“更真实”？

不能只看模型自评分。需要同时报告自动量表、事实一致性、泄漏率、人工自然度、人格可区分性、跨会谈一致性和评审者一致性；至少两名心理学背景评审者独立评分，并报告加权 Kappa、均值、方差、置信区间和失败案例。

### 9. 主要创新点是什么？

目前可以提出三个待检验的研究点：证据化画像是否改善事实忠实度；规划与表达分离是否改善披露节奏；人格和情绪机制是否增加合理的互动多样性。创新性还需要文献对比，效果需要消融与独立评审支持，不能只凭模块组合下结论。

### 10. 最大风险是什么？

主要有四类：基础数据偏差被放大；评分模型与生成模型同源导致自我偏好；人格模型刻板化；自动指标提升但临床合理性下降。对应措施是固定测试集、异源或人工复评、专家审核、版本化和强制回滚门槛。

### 11. 技术框架和一次回答的调用成本是什么？

Python 负责流程，Pydantic 定义结构契约，Jinja2 渲染提示词，模型通过 OpenAI-compatible API 返回结构化结果。默认 `compact_patientact` 每轮有一次规划、一次台词生成；泄漏修复及网关重试可能增加实际请求数。咨询师、会后处理与评分调用另计，不能把两次调用当作完整一轮的总成本。

### 12. 可以列出当前状态参数吗？

| 参数 | 当前实现 |
|---|---|
| routine/basic/moderate/sensitive/deep 阈值 | 0.25 / 0.30 / 0.40 / 0.55 / 0.70 |
| 信任：显著降/轻微降/不变/轻微升/显著升 | −0.12 / −0.06 / 0 / +0.03 / +0.06 |
| 跨会谈信任 | 初始值 + 0.5 ×（上场结束值 − 初始值）；系数可配置 |
| 会谈内疲劳 | 每轮 +0.025，阻抗行为额外 +0.025 |
| 跨会谈疲劳 | 减少 0.25，下限 0.1 |

这些均是工程参数。状态改善来自预设映射，不能再拿它作为独立证据证明咨询有效。

如果老师追问计算细节，可以用下面的公式说明。令 `g` 为反应与行为映射得到的进展信号，`clip` 表示限制到 0–1；程序还会保留四位小数：

| 状态 | 每轮更新 |
|---|---|
| 信任 T | `clip(T + 信任等级对应增量)` |
| 希望 H | `clip(H + 0.05 × g)` |
| 痛苦 D | `clip(D − 0.04 × g)` |
| 效价 V | `clip(V + 0.03 × g)` |
| 唤醒 A | `clip(A − 0.02 × g)` |
| 阻抗 R | `clip(R + 0.08 × (目标值 − R))`，目标值为阻抗行为 0.8、其他行为 0.25 |

`g` 的基础值为：更加清楚 +0.07、产生希望 +0.05、被理解 +0.02、被误解 −0.06、害怕 −0.05、被挑战 −0.02、无反应 0；洞察行为再加 0.03，讨论计划再加 0.02。当前反应强度虽然进入规划信号，但没有进一步作为这些公式的数值乘数。

举一个纯计算示例：本轮“被理解 + 简短回应”，所以 `g=0.02`。若希望原为 0.40，则更新为 0.401；痛苦原为 0.60，则更新为 0.5992。信任由独立等级决定，可以仍然不变。这个例子展示代码计算，不代表实际测得的治疗效果。

初始值补充：命中低落相关词时效价为 0.28，否则 0.38；命中焦虑相关词时唤醒为 0.70，否则 0.56；任一类命中时痛苦为 0.72，否则 0.60；咨询需求非空时希望为 0.40，否则 0.32。

### 13. 信息隔离还有哪些具体缺口？

规划器的 `rationale` 会随 `turn_signal` 传给台词生成器；咨询师载荷含 `plan.objectives`；会后合并的 `theory` 主要检查键名，摘要也会接触计划。需逐段核对请求载荷、实际台词和持久化记忆。近似文本检查能够拦截部分越界，但不能保证覆盖所有语义改写。

### 14. 测试通过是否证明模拟来访者真实？

自动化测试主要验证数据契约、状态规则与控制流程。真实性需要真实模型轨迹、跨会谈检查和心理学背景人员评审。116 个待复核项也是缓存中抽取项的统计，不能直接解释成病例错误率或人工审核结果。
